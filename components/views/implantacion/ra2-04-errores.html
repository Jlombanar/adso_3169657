CHECKLIST DE ERRORES COMUNES

Si algo falla, revisen esto

SíntomaCausa probableSolución
Build failed / error en npm installConflicto de dependencias o Root Directory incorrecto.Usar npm install --legacy-peer-deps y verificar que Root Directory sea backend.
"Cannot find module" al arrancarFalta un paquete en package.json o error de mayúsculas en un import (Linux distingue mayúsculas).Verificar nombres de archivos y que el paquete esté en dependencies.
El servicio inicia y se cae / no respondePuerto fijo en vez de process.env.PORT.Usar el puerto de la variable de entorno.
Error de conexión a Supabase / la lista de helados llega vacíaSUPABASE_URL o SUPABASE_KEY mal escritas o faltantes en Render.Compararlas con Supabase → Project Settings → API, corregirlas en Environment y redesplegar.
Imágenes no se subenFaltan variables de Cloudinary.Registrar las tres CLOUDINARY_* y redesplegar.
Falla el login con GoogleFalta GOOGLE_CLIENT_ID o no coincide con el que usa la app.Registrar la variable con el mismo Client ID configurado en Google Cloud Console.
Funciona en Postman pero no en Flutter WebCORS.Verificar app.use(cors()) en el backend.
Primera petición tarda ~1 minutoServicio gratuito dormido.Es normal; esperar, mostrar un indicador de carga o configurar el monitor de UptimeRobot.
El monitor de UptimeRobot marca DownLa ruta /health no existe o no se ha desplegado.Abrir la URL con /health en el navegador; si no responde OK, hacer push y revisar los logs.
🧠 Cierre
  • Un servidor de aplicaciones ejecuta la lógica y guarda los secretos; la app móvil solo es el cliente.
  • Render construye con el Build Command y arranca con el Start Command, usando el Root Directory.
  • El .env nunca va a GitHub: se registra en Render, variable por variable.
