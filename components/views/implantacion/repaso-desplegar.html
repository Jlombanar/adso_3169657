El backend en Render, paso a paso

Render es una PaaS: se conecta el repositorio de GitHub y la plataforma construye y ejecuta la app. Usamos un Web Service porque el backend recibe peticiones HTTP.

1
Preparar el backend: script "start": "node server.js" (en el servidor no se usa nodemon), puerto con process.env.PORT || 3000 y .gitignore con node_modules/, .env y uploads/.
2
Crear el Web Service: Branch main, Root Directory backend, Build npm install --legacy-peer-deps, Start npm start, Instance Type Free.
3
Variables de entorno: el .env nunca va a GitHub. Se registra en Render variable por variable: SUPABASE_URL, SUPABASE_KEY, las tres CLOUDINARY_*, GOOGLE_CLIENT_ID…
4
Probar con Postman: listar, login y crear con foto.
5
UptimeRobot: ruta liviana /health que responde "OK" y un monitor HTTP(s) cada menos de 15 minutos.
6
Conectar Flutter: en api_config.dart poner useRemote = true con la URL https://…onrender.com/api, y generar el APK con flutter build apk --release.
⚠️
Límites del plan gratuito
Se duerme tras 15 minutos sin tráfico y tarda cerca de un minuto en despertar. El disco es efímero, por eso las fotos van a Cloudinary. No permite SMTP, por eso el correo va con Brevo. Hay 750 horas al mes por workspace.
