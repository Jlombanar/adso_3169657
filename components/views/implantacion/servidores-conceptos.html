SERVIDORES · 1

¿Qué es un servidor?

Un servidor es un computador (o un programa que corre en uno) cuya función es atender peticiones de otros equipos llamados clientes y entregarles una respuesta: una página, datos, un archivo, un correo.

📱 Cliente
(app Flutter, navegador)
→ petición →
🖥️ Servidor
procesa la solicitud
→ respuesta →
📱 Cliente
muestra el resultado
🍽️
Analogía del restaurante
El cliente es el comensal, la petición es el pedido, el servidor es la cocina y la respuesta es el plato. El comensal no entra a la cocina: solo recibe lo que pidió.
🔁
Modelo cliente-servidor
El cliente siempre inicia la conversación (por ejemplo un GET /api/productos) y el servidor siempre espera, escucha en un puerto y responde.
🌍
Dirección y puerto
Para que lo encuentren necesita una dirección (IP o dominio) y un puerto. En local es localhost:3000; en Render es una URL pública con HTTPS.
⏱️
Siempre disponible
Un servidor debe estar encendido y conectado las 24 horas. Su computador de clase no lo cumple: se apaga, cambia de red y no tiene IP pública.
💡
Servidor = rol, no solo un equipo
Cuando ejecutan npm run dev, su computador ya está actuando como servidor, pero solo para ustedes. Desplegar es llevar ese mismo rol a un equipo que siempre está en línea y es accesible desde internet.

Tipos de servidores según su función

Un mismo sistema suele usar varios servidores, cada uno con una tarea distinta.

TipoQué haceEjemplosEn nuestro proyecto
Servidor webEntrega páginas y archivos estáticos por HTTP/HTTPS.Nginx, ApacheRender lo usa por delante de nuestra app.
Servidor de aplicacionesEjecuta la lógica de negocio: valida, calcula, consulta datos y arma respuestas (normalmente JSON).Node.js + Express, Tomcat, Django, SpringNuestro backend de Helados Mimos.
Servidor de base de datosGuarda y consulta los datos de forma organizada y segura.MongoDB, PostgreSQL, MySQLSupabase (PostgreSQL).
Servidor de archivos / multimediaAlmacena y sirve archivos como imágenes, videos y documentos.Cloudinary, Amazon S3Imágenes de productos.
Servidor de correoEnvía y recibe correos electrónicos.Brevo, Gmail (SMTP)Solo si el proyecto envía correos (verificación, recuperación).
Servidor de autenticaciónVerifica la identidad del usuario.Google OAuth, Firebase AuthLogin con Google.
Servidor DNSTraduce nombres de dominio a direcciones IP.DNS de Google, CloudflareConvierte onrender.com en una IP.
Servidor proxy / balanceadorIntermedia o reparte el tráfico entre varios servidores.Nginx, HAProxyLo gestiona Render.
Servidor de transferencia (FTP/SFTP)Transferencia de archivos entre equipos.FileZilla Server, vsftpdNo lo usamos.
🧱
Servidor web vs. servidor de aplicaciones
El servidor web entrega contenido ya hecho (un HTML, una imagen). El servidor de aplicaciones ejecuta código para generar la respuesta en cada petición. Express es un servidor de aplicaciones: cada ruta ejecuta una función que consulta la base de datos y responde.
SERVIDORES · 3

Tipos de servidores según dónde y cómo se alojan

La otra forma de clasificarlos es por quién administra el equipo y cuánto trabajo queda para el desarrollador.

ModeloCómo funcionaQuién administraVentajas / desventajasEjemplos
Servidor físico propio (on-premise)Equipo dentro de la empresa: torre, rack o blade.La empresa, todo.Control total y datos en casa; costo alto, energía, enfriamiento y mantenimiento.Sala de servidores de una empresa
Colocation / hosting dedicadoEquipo propio o alquilado dentro de un centro de datos.Cliente el software, proveedor la infraestructura física.Buena conectividad; sigue siendo costoso.Centros de datos regionales
Servidor virtual (VPS / IaaS)Máquina virtual alquilada en la nube.El desarrollador instala y administra el sistema operativo, Node, firewall y actualizaciones.Flexible y escalable; exige conocimientos de administración.AWS EC2, DigitalOcean, Google Compute Engine
Plataforma como servicio (PaaS)Se conecta el repositorio y la plataforma construye y ejecuta la app.La plataforma administra el servidor; el desarrollador entrega código y variables.Muy rápido para desplegar; menos control fino.Render, Heroku, Railway
Serverless / funcionesSe sube una función que se ejecuta solo cuando llega una petición.El proveedor; se paga por uso.Escala sola; menos adecuado para procesos largos.AWS Lambda, Vercel Functions
Backend como servicio (BaaS)Base de datos, autenticación y almacenamiento ya hechos, consumidos por API.El proveedor.Menos código de servidor; dependencia del proveedor.Supabase, Firebase
🎯
Dónde estamos nosotros
Backend en Render (PaaS), base de datos en Supabase, imágenes en Cloudinary y login con Google: la solución usa varios servidores especializados conectados por API.
📈
Escalabilidad
Vertical: darle más CPU o memoria al mismo servidor. Horizontal: agregar más servidores y repartir el tráfico entre ellos.
🛡️
Requisitos de operación
Al elegir dónde desplegar se consideran disponibilidad, costo, seguridad (HTTPS y secretos), copias de seguridad y capacidad para crecer.
CONCEPTOS · 2

Servidor para el backend vs. publicar la app móvil

Son dos cosas distintas: el backend se ejecuta en un servidor; la app móvil se distribuye a los teléfonos.

AspectoBackend (Node.js / Express)Aplicación móvil (Flutter)
Dónde correEn un servidor siempre encendido (Render, VPS, etc.).En el teléfono de cada usuario.
Cómo se entregaSe despliega desde un repositorio (GitHub) y se ejecuta con npm start.Se compila a APK / AAB (Android) o IPA (iOS) y se publica en las tiendas o se instala directamente.
Quién lo actualizaEl desarrollador, con un nuevo despliegue: todos los usuarios ven el cambio al instante.El usuario debe actualizar la app para recibir cambios.
Secretos (.env)Viven aquí: llaves de base de datos, JWT, Cloudinary, Brevo.Nunca deben ir dentro de la app: cualquiera podría extraerlos del instalador.
Qué necesita del otroUna URL pública con HTTPS y CORS configurado.La URL del backend (baseUrl) apuntando al servidor, no a localhost.
💡
Idea clave
La app móvil es solo el cliente. Toda la lógica y los secretos están en el servidor de aplicaciones; por eso desplegar bien el backend es lo que hace que la app funcione para cualquier persona.
