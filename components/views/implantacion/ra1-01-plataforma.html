RA 01 · PLATAFORMA · 1

Hardware de servidores

Aunque usemos la nube, detrás siempre hay equipos físicos en un centro de datos. Conocerlos ayuda a entender qué se está alquilando y por qué cuesta lo que cuesta.

🗄️
Servidor torre
Parece un computador de escritorio grande. Barato y fácil de instalar en una oficina; ocupa espacio y no escala bien. Ideal para un negocio pequeño.
🧰
Servidor rack
Equipos planos que se atornillan en un armario (rack) estándar de 19 pulgadas. Se miden en unidades (1U, 2U). Ahorran espacio y se administran juntos.
🔲
Servidor blade
Tarjetas delgadas que comparten un chasis con energía, ventilación y red. Máxima densidad: muchos servidores en poco espacio. Típico en centros de datos.
🖥️
Máquinas virtuales
Un hipervisor (VMware, Hyper-V, VirtualBox) divide un servidor físico en varios servidores virtuales. Así funcionan los VPS y la mayoría de servicios en la nube.
Arreglo de discos (RAID)Cómo funcionaSi falla un disco…Uso típico
RAID 0Reparte los datos entre dos o más discos.Se pierde todo.Velocidad, nunca para datos importantes.
RAID 1Copia espejo: los mismos datos en dos discos.Sigue funcionando con el otro disco.Sistema operativo, bases de datos pequeñas.
RAID 5Reparte datos y paridad entre tres o más discos.Sigue funcionando y se reconstruye.Servidores de archivos.
RAID 10Combina espejo (1) y reparto (0), mínimo cuatro discos.Sigue funcionando, con buen rendimiento.Bases de datos con mucho tráfico.
☁️
¿Y en la nube?
Con Supabase, Cloudinary y Render no tenemos que comprar discos ni armar RAID: el proveedor administra el hardware por nosotros. Por eso aquí solo necesitamos conocerlo para entender qué estamos alquilando.
RA 01 · PLATAFORMA · 2

Sistema operativo, licencias, hosting y dominio

Preparar la plataforma tecnológica es decidir sobre qué sistema operativo y en qué tipo de alojamiento va a correr el software.

Sistema operativo de servidorCaracterísticasLicenciamientoCuándo se elige
Linux (Ubuntu Server, Debian, Red Hat)Liviano, estable, se administra por terminal. Es el más usado para servidores web y en la nube.Libre en su mayoría (GPL). Red Hat cobra suscripción por soporte.Aplicaciones Node.js, Python, PHP. Render ejecuta nuestro backend sobre Linux.
Windows ServerInterfaz gráfica, integración con Active Directory y tecnologías Microsoft.De pago, por núcleos del procesador y licencias de acceso de cliente.Empresas con aplicaciones .NET, SQL Server o directorio de usuarios Microsoft.
🏠
Hosting compartido
Muchos sitios en un mismo servidor. Barato y sencillo, pero pensado para páginas web y PHP, no para un backend Node.js propio.
☁️
VPS y nube
Servidor virtual propio (AWS, Azure, DigitalOcean) o plataforma administrada (Render, Heroku). En el RA 02 se comparan a fondo.
🌐
Dominio
Nombre fácil de recordar (por ejemplo heladosmimos.com.co) que el DNS traduce a la IP del servidor. Se compra a un registrador y se renueva cada año. Render entrega gratis un subdominio .onrender.com.
📤
FTP / SFTP
Protocolo para subir archivos a un servidor (FTP puerto 21, SFTP puerto 22 y cifrado), con programas como FileZilla. En Render no se usa: el código llega desde GitHub.
