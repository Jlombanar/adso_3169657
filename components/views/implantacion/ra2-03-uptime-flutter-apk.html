PASO 5 · EVITAR QUE SE DUERMA

Mantener el servicio despierto con UptimeRobot

En el plan gratuito Render duerme el servicio tras 15 minutos sin tráfico. Un monitor externo que lo visita cada pocos minutos cuenta como tráfico y evita que se apague.

🔗 Ir a UptimeRobot 🔗 Ir al panel de Render
📄 backend/server.js — ruta de salud (antes de app.listen)
// Montando las rutas de la API app.get('/health', (req, res) => { res.status(200).send('OK'); });
💡
¿Por qué una ruta /health?
Es una ruta liviana, pública y sin base de datos ni token: solo responde "OK" con código 200. Así el monitor comprueba que el servidor está vivo sin gastar recursos. Hagan git push para que Render la despliegue antes de configurar el monitor.
1
Copiar la URL pública: en el panel de Render, en la vista principal del servicio, copien la URL bajo el nombre del proyecto (por ejemplo https://helados-mimos-xxxx.onrender.com). Ábranla en otra pestaña agregando /health: debe mostrar OK.
2
Crear cuenta en UptimeRobot: entren con el botón Ir a UptimeRobot (uptimerobot.com), elijan Sign Up (tiene plan gratuito) o Log In, y confirmen que ven el Dashboard con la lista de monitores vacía.
3
Crear el monitor: botón + Add New Monitor y llenar el formulario con los datos de la tabla.
4
Verificar: tras presionar Create Monitor, el monitor debe mostrarse en verde Up.
CampoValorNota
Monitor TypeHTTP(s)Hace una petición web real al servicio.
Friendly NameBackend Render HeladosNombre para identificarlo en el panel.

⚠️
Esto es un truco para estudiar, no una solución de producción
• Render entrega 750 horas gratuitas al mes por workspace. Un servicio encendido todo el mes consume unas 744, así que solo uno cabe despierto permanentemente: si varios integrantes del equipo mantienen servicios activos en el mismo workspace, se agotan las horas y Render los suspende hasta el mes siguiente.
• El servicio puede reiniciarse en cualquier momento y el disco sigue siendo efímero.
• Para un cliente real se usa un plan de pago.
PASO 6 · CONECTAR FLUTTER

Apuntar la app a la URL pública

Hasta ahora la app hablaba con localhost o 10.0.2.2. Con el backend desplegado, usa la URL de Render.

📄 lib/services/api_config.dart
import 'dart:io' show Platform; import 'package:flutter/foundation.dart' show kIsWeb; class ApiConfig { // Cambia a false cuando quieras volver a probar con tu servidor Node.js local static const bool useRemote = true; // URL de tu backend desplegado en Render static const String _remoteUrl = 'https://helados-mimos-xxxx.onrender.com/api'; static String get baseUrl { if (useRemote) { return _remoteUrl; } // Servidor local: navegador web if (kIsWeb) return 'http://localhost:3000/api'; // Servidor local: emulador de Android (10.0.2.2 apunta al localhost de la PC) if (Platform.isAndroid) return 'http://10.0.2.2:3000/api'; // Servidor local: simulador iOS / escritorio return 'http://localhost:3000/api'; } // Los headers no cambian: se dejan como estaban static const Map<String, String> headers = { 'Content-Type': 'application/json', 'Accept': 'application/json', }; }
💡
Ventajas de este cambio
Con HTTPS ya no hace falta usesCleartextTraffic en el AndroidManifest, y la app funciona en un teléfono físico sin depender del computador. Para volver a desarrollar en local, basta cambiar useRemote a false.
⏳
Primera petición lenta
Si el servicio estaba dormido, la primera llamada puede tardar cerca de un minuto. Conviene mostrar un indicador de carga en la app para que el usuario no crea que se bloqueó.
PASO 7 · GENERAR EL APK

Crear el APK de Flutter para instalar en un celular

El APK es el instalador de la app para Android. Con el backend ya en Render, el APK funciona en cualquier teléfono con internet, sin depender de su computador.

1
Verificar la URL: en api_config.dart debe estar useRemote = true. Si queda en false, el APK intentará conectarse a 10.0.2.2 y no funcionará fuera del emulador.
2
Permiso de internet: los builds de release necesitan declarar el permiso en el manifiesto principal (ver código abajo). Sin él, la app funciona en modo debug pero en el APK no se conecta.
3
Limpiar y generar: ejecutar los comandos de la terminal, dentro de la carpeta del proyecto Flutter (donde está el pubspec.yaml).
4
Ubicar el archivo generado y pasarlo al celular.
📄 android/app/src/main/AndroidManifest.xml — permiso de internet
<manifest xmlns:android="http://schemas.android.com/apk/res/android"> <uses-permission android:name="android.permission.INTERNET"/> <application android:label="Helados Mimos" android:name="${applicationName}" android:icon="@mipmap/launcher_icon"> <!-- ... el resto del archivo queda igual ... --> </application> </manifest>
⚠️
Solo agreguen la línea del permiso
La línea uses-permission va dentro de <manifest>, antes de <application>. No reemplacen su archivo completo: el resto (activity, meta-data, etc.) debe quedar como está. El android:label es el nombre que se ve bajo el ícono, y launcher_icon es el ícono generado con flutter_launcher_icons; si no lo han generado, dejen el que ya tienen (@mipmap/ic_launcher).
💻 Terminal de VS Code (en la carpeta del proyecto Flutter)
flutter clean flutter pub get flutter build apk --release
📋 Salida esperada
Running Gradle task 'assembleRelease'... ✓ Built build/app/outputs/flutter-apk/app-release.apk (xx.xMB)
ComandoQué generaCuándo usarlo
flutter build apk --releaseUn solo APK que funciona en todos los celulares Android.Para compartir y probar en clase. Es el más sencillo.
flutter build apk --split-per-abiUn APK por arquitectura (arm64, armeabi, x86_64), cada uno más liviano.Cuando el tamaño importa; el de arm64-v8a sirve para la mayoría de celulares actuales.
flutter build appbundleUn archivo .aab para subir a Google Play.Publicación en la tienda (requiere firma con keystore propio).
📁 Dónde queda el archivo
tu_proyecto_flutter/ └── build/ └── app/ └── outputs/ └── flutter-apk/ └── app-release.apk
📲
Instalar en el celular
Pasen el APK por cable USB, Drive o WhatsApp (como documento). En el teléfono ábranlo y permitan "instalar apps de orígenes desconocidos" cuando lo pida.
🔌
Instalar por cable (opcional)
Con el celular conectado y la depuración USB activa: flutter install o adb install app-release.apk.
⏳
Primer uso
Si Render estaba dormido, el primer inicio de sesión tarda cerca de un minuto. Es normal si no está activo el monitor de UptimeRobot.
🔏
Sobre la firma del APK
Por defecto, flutter build apk --release firma el APK con la clave de depuración. Sirve para pruebas y para la sustentación, pero no para publicar en Google Play: allí se necesita un keystore propio, que se guarda con cuidado y nunca se sube a GitHub.
ProblemaCausa probableSolución
La app funciona en el emulador pero el APK no carga datosFalta el permiso INTERNET o useRemote está en false.Agregar el permiso, verificar useRemote = true y generar el APK de nuevo.
El APK sigue mostrando el ícono de FlutterNo se ejecutó el generador de íconos o hay caché.Correr dart run flutter_launcher_icons, luego flutter clean y volver a compilar.
Error de Gradle / SDK al compilarLicencias de Android sin aceptar o SDK incompleto.Ejecutar flutter doctor y flutter doctor --android-licenses, y seguir lo que indique.
El celular no deja instalarInstalación desde orígenes desconocidos bloqueada o versión anterior con otra firma.Permitir la instalación y desinstalar la versión vieja antes.
